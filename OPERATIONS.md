# Работа в терминале

## Подготовить знания

```bash
./install.sh
./mra-cli sources
./mra-cli project
./mra-cli doctor
./mra-cli product 44167
```

Установка создаёт `data/mra.sqlite3` и подключает комплектные правила v2.1, 490 карточек канона и 1817 связей Ozon. Повторная установка с теми же источниками не меняет существующие материалы и обращения. Изменение утверждённого источника не выполняется автоматически.

`project` показывает фактический состав и очередь. `sources` проверяет файлы по контрольным суммам. `doctor` сверяет рабочую базу с комплектом знаний. Код возврата 0 означает успешные локальные проверки; доступ к внешней модели и отправка на площадку в эту проверку не входят.

## Посмотреть точный запрос без сети

```bash
./mra-cli preview --article 44167 --question 'Как подключить эти наушники к телефону?'
```

Вывод содержит действующие правила, карточку выбранного товара, настройки модели и ожидаемую схему ответа. Ключей и заголовков авторизации в нём нет. Preview ничего не генерирует и не меняет очередь.

## Загрузить обращение

```bash
# Проверочный вопрос с реальным артикулом; это не обращение покупателя.
./mra-cli import-json examples/inbox.example.json
./mra-cli queue --state new
./mra-cli show check_44167_001

# Прочитать до 100 текущих обращений из БД старого коллектора.
./mra-cli import-legacy --source /absolute/path/to/service.sqlite3 --limit 100
```

Вход JSON содержит площадку, кабинет, внешний ID, тип `question`/`review`, текст и артикул либо hints. Пример данных: examples/inbox.example.json. SKU Ozon разрешается по карте своего кабинета. Неизвестные или неоднозначные связи не подменяются совпадением из другого кабинета.

## Генерация и просмотр

```bash
# Ключ читается из указанного файла в момент запроса; в Git он не входит.
export MRA_OPENAI_KEY_FILE="/absolute/path/to/provider-key.txt"
./mra-cli run --limit 1 --dry-run
./mra-cli run --limit 1 --live
./mra-cli show check_44167_001
./mra-cli review check_44167_001 --operator 'Имя оператора'
./mra-cli outbox
```

`--live` разрешает вызов провайдера для выбранных обращений. Перед генерацией для настроенного кабинета обновляется каталог, если снимок старше суток либо не удалось определить товар. На один кабинет выполняется одна попытка обновления в рамках пакетной команды. Ошибка обновления не запускает бесконечные повторы. Без актуального каталога настроенного кабинета ответ передаётся оператору без обращения к модели.

`review` показывает обращение и черновик. Действия: 1 — подтвердить в HOLD, 2 — вставить исправленный текст, 3 — отклонить с причиной, 4 — исходные факты товара, 5 — правила, 6 — история решений. Правка заканчивается строкой `/готово`, отменяется строкой `/отмена`. Правка создаёт новый черновик; его нужно подтвердить отдельно. Старый текст сохраняется, старый HOLD отменяется. При изменении обращения, правил или материала подтвердить устаревший черновик нельзя.

Для первого знакомства дважды откройте `mra.command` в Finder либо выполните `./mra-cli terminal`. Учебный пункт меню использует отдельную базу, настоящий канон и явно обозначенный ответ, подготовленный вручную. Модель не вызывается. Пункт одного вызова модели требует отдельного ввода `ВЫЗВАТЬ`; ошибка провайдера не повторяется автоматически. Рабочая база не смешивается с учебной.

Неинтерактивные команды для того же процесса:

```bash
./mra-cli approve MESSAGE_ID --draft-id DRAFT_ID --operator 'Имя'
./mra-cli revise MESSAGE_ID --draft-id DRAFT_ID --text-file /absolute/path/to/reply.txt --operator 'Имя'
./mra-cli reject MESSAGE_ID --draft-id DRAFT_ID --reason 'Причина' --operator 'Имя'
./mra-cli trace MESSAGE_ID --full
```

`approve` означает локальный HOLD. Отправка выполняется отдельно через delivery-preview и deliver либо действие 8 терминала. Перед ней человек видит окончательное назначение и текст, а программа перечитывает обращение и существующие ответы. Подключения и восстановление: [CONNECTORS.md](CONNECTORS.md); совместный прогон: [FIELD_TEST.md](FIELD_TEST.md). `./mra-cli readiness` показывает локальную целостность и состояние живых проверок раздельно.

При нехватке данных или ошибке провайдера обращение получает `needs_data` с причиной. После устранения причины один явный повтор: `./mra-cli retry MESSAGE_ID --live`. Автоматических повторов нет. Если старый процесс остановлен, но состояние осталось `processing`, команда `recover MESSAGE_ID` отменяет его токен захвата и возвращает обращение в `new`.

## Настройки

| Переменная | По умолчанию |
|---|---|
| `MRA_DB_PATH` | `data/mra.sqlite3` внутри checkout |
| `MRA_ACCOUNTS_FILE` | `data/accounts.json`, если существует; иначе `examples/accounts.example.json` |
| `MRA_DATA_DIR` | `data/` внутри checkout |
| `MRA_RULES_FILE` | Комплектный `knowledge/ПРАВИЛА ОТВЕТОВ.md` |
| `MRA_OPENAI_KEY_FILE` | Не задана; ключи автоматически не ищутся |
| `OPENAI_API_KEY` | Альтернатива файлу ключа |
| `MRA_MODEL` | `gpt-6.1-sol` |
| `MRA_PROVIDER` | `openai`; альтернативный явный выбор — `openrouter` |
| `OPENROUTER_API_KEY` | Ключ OpenRouter из окружения |
| `MRA_OPENROUTER_KEY_FILE` | Файл с одним ключом OpenRouter, без копирования в проект |
| `MRA_OPENROUTER_AUTH_FILE` | Явно указанный JSON-хранилище терминальной авторизации: запись openrouter с type=api и key |
| `MRA_REASONING_EFFORT` | `high` |
| `MRA_TIMEOUT_SECONDS` | `90` |
| `MRA_MAX_OUTPUT_TOKENS` | `2000`, включая reasoning-токены |
| `MRA_DISABLE_LLM` | `1` отключает вызовы даже при `--live` |
| `MRA_PYTHON` | `python3` |
| `MRA_OPERATOR` | Имя для журналирования ручных решений; в меню — имя пользователя macOS |

Для текущей сборки используются комплектные правила. Переопределение файла владельцем видно в конфигурации; doctor перестаёт подтверждать соответствие комплекту, если файл отличается.

### OpenRouter

Провайдер выбирается явно. Ошибка OpenAI не переключает модель автоматически. Для OpenRouter по умолчанию используется идентификатор openai/gpt-6.1-sol; его можно переопределить через MRA_MODEL. Отправляются те же правила, выбранная карточка и вопрос, но в формате Chat Completions с JSON Schema. Автоматические повторы и маршрутизация на запасного провайдера отключены. Доступны только два фиксированных адреса API; произвольный endpoint для отправки ключа не задаётся.

```bash
MRA_PROVIDER=openrouter MRA_OPENROUTER_KEY_FILE=/absolute/path/to/openrouter-key.txt ./mra-cli preview --article 44167 --question 'Как подключить эти наушники к телефону?'
MRA_PROVIDER=openrouter MRA_OPENROUTER_KEY_FILE=/absolute/path/to/openrouter-key.txt ./mra-cli terminal
```

Для существующего JSON-хранилища терминала вместо KEY_FILE указывается MRA_OPENROUTER_AUTH_FILE. Без явного указания этот файл не ищется и не читается. Передача содержимого проекта посреднику и выбранному провайдеру требует согласованного состава данных. Измеренные prompt_tokens/completion_tokens переводятся в общий журнал; полный usage, включая cost при наличии, остаётся в снимке ответа.

## Копии и восстановление

```bash
./mra-cli backup /absolute/path/to/new-backup.sqlite3
./mra-cli migrate-db --source /absolute/path/to/new-backup.sqlite3 --target /absolute/path/to/restored.sqlite3
./mra-cli --db /absolute/path/to/restored.sqlite3 doctor
```

Копирование выполняется SQLite Backup API. Источник открывается read-only, существующий файл назначения не перезаписывается. Для перехода с 1.1.0 используется тот же migrate-db; старые подтверждения требуют новой проверки. Чтобы подключить комплектный канон к отдельно выбранной БД, используйте `./mra-cli --db PATH import-bundled`. Изменение уже имеющегося отличающегося материала требует явного `--replace-materials` и согласованного источника владельца.

Рабочие SQLite и обращения в Git не включаются. Исходные правила и канон этой сборки, напротив, входят в knowledge/ и проверяются при установке.

Матрица товаров: [ASSORTMENT.md](ASSORTMENT.md). Состав и границы журнала: [AUDIT.md](AUDIT.md).


## Автономный режим и первый запуск

Самостоятельная фоновая работа и допуск к автопубликации описаны в [AUTONOMOUS_MODE](AUTONOMOUS_MODE.md): текущие компоненты, план работы без терминала, постепенное включение по кабинетам/категориям, исключения и оставшиеся задачи. Фоновый авторежим пока не реализован и не включён.

Для первого запуска используйте **start.command**: кабинет → провайдер → заполнение файлов в private/credentials → локальная проверка и проверка API → СТАРТ. Инструкция: [START_HERE](START_HERE.md). Папка private/ игнорируется Git.
