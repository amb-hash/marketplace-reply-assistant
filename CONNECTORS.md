# Подключения к маркетплейсам

Вопросы и отзывы WB, Ozon и Яндекс Маркета читаются собственными клиентами MRA. Создание нового ответа доступно отдельной командой после проверки человеком. Одобрение сохраняет HOLD и само по себе ничего не публикует.

## Кабинеты и доступ

В accounts JSON хранятся настройки шести кабинетов: примеры в examples/accounts.example.json, локальные настройки в data/accounts.json. В настройке только имена переменных окружения или пути к отдельным файлам ключей. Содержимое ключей не копируется в проект.

Первый натурный тест — Ozon Deppa, account_id=acct_deppa_ozon («Озон старший»). У остальных кабинетов собственные идентификаторы и матрицы; обращения не объединяются.

Для Ozon нужны Api-Key и Client-Id. Актуальный справочник требует Premium Plus для вопросов, подписку «Управление отзывами» или Premium Pro для отзывов. Права чтения/записи ключа не заменяют подписку. Для WB нужна категория «Вопросы и отзывы»; предусмотрен персональный или сервисный токен. Для Яндекс Маркета нужен доступ communication либо all-methods; при нескольких кабинетах задайте business_id явно.

## Маршруты

| Площадка | Чтение | Создание ответа |
|---|---|---|
| WB, вопрос | GET /api/v1/questions; /api/v1/question | PATCH /api/v1/questions: id, answer.text, state=wbRu |
| WB, отзыв | GET /api/v1/feedbacks; /api/v1/feedback | POST /api/v1/feedbacks/answer: id, text |
| Ozon, вопрос | POST /v1/question/list; /v1/question/info; /v1/question/answer/list | POST /v1/question/answer/create: question_id, целочисленный sku, text |
| Ozon, отзыв | POST /v2/review/list; /v2/review/info; /v1/review/comment/list | POST /v1/review/comment/create: review_id, text, mark_review_as_processed=true |
| Яндекс, вопрос | POST /v1/businesses/{id}/goods-questions; /goods-questions/answers | POST /goods-questions/update: operationType=CREATE, parentEntityId типа QUESTION, text |
| Яндекс, отзыв | POST /v2/businesses/{id}/goods-feedback; /goods-feedback/comments | POST /goods-feedback/comments/update: feedbackId, comment.text |

Клиент не удаляет ответы, не редактирует опубликованный текст и не управляет заказами, ценами или возвратами. Разрешены только перечисленные операции создания ответа. HTTP-перенаправления не проходят: ключ не пересылается на другой адрес.

Общий SQLite-лимитер координирует каталог и обращения всех процессов одной установки. Квоты методов и кабинета резервируются атомарно, 420/429 и серверные сроки восстановления сохраняются после перезапуска. Подробные политики: [RATE_LIMITS](RATE_LIMITS.md).

inbox-sync получает ограниченную выборку, а не полный исторический архив. Для Яндекса действует период API по умолчанию. Вопросы Ozon с уже имеющимися ответами не выбираются для новой генерации: по одному author_name нельзя надёжно установить владельца ответа. Если ответ появился между получением вопроса и отправкой, MRA останавливает запись.

## Одобрение и восстановление

1. inbox-sync сохраняет обращение, кабинет, тип, внешний ID и товарные идентификаторы. Новая версия обращения отменяет прежнее одобрение.
2. Модель вызывается отдельно. Человек сверяет факты и текст, правит либо одобряет в HOLD.
3. delivery-preview создаёт задание с точным назначением, ревизией и SHA-256 текста. Для локально придуманного вопроса отправка недоступна.
4. deliver требует --live, имя оператора и SHA-256 просмотренного текста. Перед записью заново читаются обращение и ответы. Изменённый вопрос, чужой кабинет, устаревшее одобрение или имеющийся ответ останавливают запись.
5. Перед записью сохраняется устойчивый признак начала попытки. Второй процесс не может отправить то же задание. После начала записи локальные правка и повторное одобрение заблокированы до разбора результата.
6. accepted означает принятие запроса API; observed — тот же текст прочитан из API; published — площадка явно подтвердила публикацию. HTTP 200 не заменяет подтверждение видимости.
7. При потерянном ответе сервера или сбое после начала записи — uncertain. delivery-reconcile только читает. Отсутствие текста при чтении не доказывает неотправку.
8. delivery-recover восстанавливает прерванную проверку до записи. Подтверждённый отказ HTTP 400/401/403/422/429 можно снять вручную только при наличии сохранённого ответа API, затем заново подготовить и проверить задание. Сброс uncertain или успешной отправки запрещён.

SQLite координирует операторов, работающих с одним файлом. API площадок не дают атомарно запретить ответ коллеги, сделанный в кабинете между последним чтением и POST. На первом тесте отправкой управляет один оператор, остальные проверяют текст и наблюдают результат. При модерации Ozon комментарий может ещё не возвращаться списком: сохраняется accepted/uncertain, повтор не запускается.

## Команды

```bash
./mra-cli readiness
./mra-cli access-check --account acct_deppa_ozon --live
./mra-cli catalog-sync --account acct_deppa_ozon --live
./mra-cli inbox-sync --account acct_deppa_ozon --kind question --limit 5 --live
./mra-cli generate MESSAGE_ID --live
./mra-cli review MESSAGE_ID --operator 'Имя'
./mra-cli delivery-preview MESSAGE_ID --draft-id DRAFT_ID --operator 'Имя'
./mra-cli deliver JOB_ID --text-sha256 SHA256 --operator 'Имя' --live
./mra-cli delivery-reconcile JOB_ID --operator 'Имя' --live
./mra-cli delivery-status
```

У двух кабинетов каждой площадки общий код клиента и отдельные настройки. --all у access-check и inbox-sync проходит все настроенные кабинеты и показывает результат каждого. Модель при чтениях не вызывается.

## Основания контрактов

- [Официальный WB API](https://dev.wildberries.ru/en/docs/openapi/customer-communication#tag/questions/operation/patchV1Questions): текущие схемы и значение wbRu, сверено в браузере 29.10.2026.
- [Официальный Seller API Ozon](https://docs.ozon.ru/api/seller/): текущие схемы, v2/review, integer SKU и подписки, сверено в браузере 29.10.2026. Старый гайд 2024 года не заменяет актуальную схему отзывов.
- [Официальная OpenAPI-спецификация Яндекс Маркета](https://github.com/yandex-market/yandex-market-partner-api): пути и DTO, сверено с [документацией вопросов](https://yandex.ru/dev/market/partner-api/doc/ru/reference/goods-questions/updateGoodsQuestionTextEntity) и [комментариев](https://yandex.ru/dev/market/partner-api/doc/ru/reference/goods-feedback/updateGoodsFeedbackComment).

Доказательства проверки в data/readiness-20261029 не входят в Git. Основная инструкция: [README](README.md).


## Один вопрос в терминале

`./mra-cli work MESSAGE_ID` показывает реальное обращение и подготовленный ответ. Ввод ОПУБЛИКОВАТЬ означает одобрение показанного текста и одну отправку; ОТКЛОНИТЬ сохраняет причину без отправки. Перед записью действуют все проверки delivery.

Для известного Ozon SKU допускается свежая запись remote_inputs не старше суток с неизменным отпечатком вопроса и однозначной картой именно этого кабинета. В этом случае обработка одного обращения не требует права чтения всего каталога. Полнота матрицы от этого не подтверждается. Неизвестный, конфликтующий или изменившийся SKU требует обновления каталога либо проверки владельцем. Полный каталог не подменяется одним вопросом.
