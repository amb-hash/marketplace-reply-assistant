# Правила и каноны: обязательная часть проекта

Полный комплект MRA включает исполняемый код, действующий файл правил, готовый канон, карту идентификаторов и работающую загрузку этих источников. Наличие демо или зелёных тестов кода не заменяет подключение рабочих знаний.

## Рабочие источники этой сборки

| Источник | Файл внутри проекта | Проверяемый результат |
|---|---|---|
| Правила общения | `knowledge/ПРАВИЛА ОТВЕТОВ.md` | Версия 2.1, файл реально используется в запросе |
| Факты о товарах | `knowledge/КАНОН ДЛЯ АГЕНТА.md` | 490 уникальных артикулов, 16 категорий |
| SKU → артикул | `knowledge/ozon-mapping.json` | 1817 связей; ключ включает площадку и кабинет |
| Происхождение | `knowledge/SOURCES.json` | Исходные проектные пути, SHA-256 и ожидаемые объёмы |

Правила скопированы из корневого файла проекта. Канон скопирован из `2026-10-08 – 17-52-13 – Готовый канон/Канон для агента/КАНОН ДЛЯ АГЕНТА.md`. Обе копии побайтно совпадают с оригиналами. Старые папки «на проверку», «каноны v2» и материалы расследования не подмешиваются к этому канону.

Карта получена из проектной выгрузки Ozon от 6 октября 2026 года. Перенесены только поля площадки, кабинета, SKU и артикула. Файлы ключей, пути к ключам и обращения покупателей из исходной выгрузки не включены. Для Deppa MSK используется идентификатор кабинета, рекомендованный в исходном реестре; неоднозначные идентификаторы из старых обращений автоматически не переназначаются.

## Как источники становятся рабочими

`./install.sh` вызывает `init`. Он проверяет файлы по SOURCES.json, читает артикулы из заголовков Markdown, переносит каждый раздел в SQLite без переписывания текста и загружает карту Ozon. Для индекса не используются модели или сетевые запросы.

В SQLite сохраняется исходный текст раздела и ссылка на строки файла. Исходный Markdown остаётся отдельным файлом. Перед генерацией проверяется целостность материалов; в ответном журнале фиксируются версия канона, версия правил и использованный материал.

`doctor` проверяет не просто наличие файлов: все 490 разделов и 1817 связей должны совпасть с подключённой базой. Проверка также сверяет файл правил, контрольную сумму канона и целостность SQLite. Подмена рабочей базы синтетическим примером не даёт успешной проверки подключения.

## Покрытие

1817 — число связей SKU по кабинетам. После нормализации суффиксов 1083 связи ведут к артикулам из текущего канона; 734 связи ведут к артикулам вне него. Это ограничение имеющейся базы знаний. Для отсутствующего артикула программа передаёт обращение человеку и не выдумывает свойства.

## Изменения источников

Содержание правил и канона меняет владелец. Техническая задача по подключению не является разрешением исправлять их текст, дополнять факты или создавать каноны моделью. Новые утверждённые источники получают новые контрольные суммы и отдельную версию комплекта. Ключи и обращения хранятся вне Git; рабочие правила и канон входят в этот закрытый репозиторий как обязательные части проекта.
