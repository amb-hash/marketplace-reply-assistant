# Матрица товаров по кабинетам

MRA самостоятельно читает каталоги WB, Ozon и Яндекс Маркета через API площадок. Для запуска нужны Python, комплектные знания, собственная SQLite и ключи кабинетов. Дополнительный сервис для матрицы не требуется.

Канон отвечает за факты о товаре. Матрица отвечает за связь конкретной карточки конкретного кабинета с артикулом. Каталог маркетплейса не дописывает канон и не становится источником характеристик для ответа покупателю.

## Шесть кабинетов

| Площадка | Кабинет | ID MRA |
|---|---|---|
| Wildberries | Deppa | acct_deppa_wb |
| Wildberries | Deppa MSK | acct_deppa_msk |
| Ozon | Deppa | acct_deppa_ozon |
| Ozon | Deppa MSK | acct_deppa_ozon_msk |
| Яндекс Маркет | Deppa | acct_deppa_yandex |
| Яндекс Маркет | AXXA | acct_axxa_yandex |

Одинаковый SKU в разных кабинетах не объединяет товары. Ключ связи включает площадку, кабинет и тип внешнего ID. SKU, product_id, nmID, offerId и marketSku не считаются взаимозаменяемыми.

## Откуда берётся список

| Площадка | Чтение | Сохраняем |
|---|---|---|
| WB | POST /content/v2/get/cards/list | nmID, vendorCode, название; курсор updatedAt + nmID |
| Ozon | POST /v3/product/list, затем POST /v3/product/info/list | product_id, offer_id, SKU из sources, название и признак архива |
| Яндекс | GET /v2/campaigns при отсутствии business_id, затем POST /v2/businesses/{businessId}/offer-mappings | offerId, marketSku, название; pageToken; каталог неархивных товаров кабинета |

POST этих методов получает данные. Клиент разрешает только перечисленные маршруты чтения и не содержит методов изменения товаров, цен или ответов.

Ссылки на официальные контракты: [WB](https://dev.wildberries.ru/docs/openapi/work-with-products), [список Ozon](https://docs.ozon.ru/api/seller/#operation/ProductAPI_GetProductList), [информация Ozon](https://docs.ozon.ru/api/seller/#operation/ProductAPI_GetProductInfoList), [каталог Яндекса](https://yandex.ru/dev/market/partner-api/doc/ru/reference/business-offer-mappings/getOfferMappings), [список магазинов Яндекса](https://yandex.ru/dev/market/partner-api/doc/ru/reference/campaigns/getCampaigns).

Если токен Яндекса открывает несколько кабинетов, business_id указывается явно. Первый кабинет из ответа не выбирается автоматически. Товары разных магазинов одного business_id относятся к одному кабинету; это не утверждение о наличии товара в каждом магазине.

## Обновление

```bash
./mra-cli accounts
./mra-cli catalog-sync --all --live --max-requests 30
./mra-cli catalog-sync --account acct_deppa_ozon --live
./mra-cli matrix
./mra-cli matrix --account acct_axxa_yandex --full
./mra-cli matrix --gaps
```

Настройки берутся из data/accounts.json или MRA_ACCOUNTS_FILE. Переносимый шаблон — examples/accounts.example.json: в нём имена переменных окружения, без ключей и личных путей. Локальная настройка может содержать api_key_file и client_id_file; содержимое файлов читается только во время запроса. Для Яндекса можно добавить числовой business_id. Все пути к ключам принадлежат конкретной установке и не входят в комплект передачи.

Обновление проходит все страницы и проверяет курсоры. Максимум запросов задаётся на кабинет, включая получение дополнительной информации. HTTP 401/403/429 и сбой связи заканчивают попытку. Один неуспешный кабинет не мешает проверить остальные.

Только полный снимок одной транзакцией обновляет матрицу. Прерванная загрузка сохраняет прежний успешный снимок. Отчёт отдельно показывает время наблюдения, возраст, результат последней попытки и её ошибку. Отсутствие снимка отображается как null, а не нулевой ассортимент.

## Новые, исчезнувшие и неоднозначные товары

- Новая карточка появляется в отчёте added. Если артикул уже есть в каноне, инструмент использует существующие факты после сопоставления обращения.
- Если канона нет, товар виден в matrix --gaps, ответ получает needs_data. Модель не придумывает карточку и не дополняет знания.
- Отсутствие в следующем полном снимке отмечается missing. Это отсутствие в выбранном источнике каталога; оно не доказывает нулевой остаток или прекращение продаж. История связи остаётся доступна для старых вопросов и отзывов.
- Вернувшаяся карточка отмечается returned.
- Если один внешний ID ведёт к разным артикулам, связь отмечается неоднозначной. Артикул не выбирается случайно. Точный offerId или артикул продавца может определить товар независимо от неоднозначного marketSku.
- Если связь артикула изменилась, сохранённые обращения пересопоставляются. Изменение товара увеличивает ревизию обращения и отменяет прежний HOLD. Чужой кабинет не затрагивается.

Матрица показывает состав карточек, отдельно от складского наличия и возможности заказа. Автоматические фоновые задания этой сборкой не устанавливаются. При ручном тесте catalog-sync запускается командой; run/retry дополнительно проверяют свежесть нужного кабинета перед генерацией. Порог свежести — 24 часа. Неизвестный товар вызывает одну попытку обновления каталога в рамках запуска.

Полный снимок можно импортировать без сети через catalog-import PATH. Формат: schema_version=1, marketplace, account_id, observed_at с часовым поясом, complete=true, listings. Каждая строка содержит listing_id, seller_article, title, status (listed/archived), aliases — пары типа ID и значения. Более старый или неполный снимок не заменяет новый.
