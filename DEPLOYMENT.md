# Развёртывание для следующего оператора

## Что получить

Полный комплект MRA 1.3.0: код, knowledge/, действующие правила v2.1, канон 490 артикулов, карту Ozon и инструкции. Источники сверяются с knowledge/SOURCES.json. Передавайте исходный архив, собранный tools/package_release.py по RELEASE_FILES.txt; рабочие SQLite, обращения и ключи в исходный архив не входят. Версия пока проходит натурную приёмку.

Нужны macOS или Linux, Python 3.9+ с SQLite и доступ к HTTPS площадок и выбранного провайдера модели. Зависимости PyPI не нужны. Проверка: `python3 --version`. Если Python отсутствует, сначала установите его штатным способом для вашей ОС.

## Доступы

| Доступ | Что обеспечить |
|---|---|
| Ozon Deppa | Отдельный Api-Key для MRA и Client-Id именно этого кабинета; чтение каталога, вопросов и создание ответов |
| Вопросы Ozon | Premium Plus; одного ключа с правом записи недостаточно |
| Отзывы Ozon | Доступ к отзывам и подписка «Управление отзывами» либо Premium Pro согласно текущей документации Ozon |
| Wildberries | Токен категорий «Контент» для каталога и «Вопросы и отзывы» для обращений; запись для отправки. Укажите тип токена при настройке |
| Яндекс Маркет | communication для обращений и записи, offers-and-cards-management:read-only для каталога либо соответствующие полные права. При неоднозначном доступе задайте business_id |
| Провайдер модели | API-ключ OpenRouter либо OpenAI, положительный баланс и доступ к выбранной модели. Подписка на чат не подтверждает баланс API |

Рекомендуемое название ключа Ozon: **MRA-Ozon-Deppa-Pilot**. Это подпись ключа в кабинете, не обязательный параметр API. У двух кабинетов каждой площадки собственные настройки. Для первого теста достаточно Ozon Deppa; остальные подключаются отдельно и проверяются по каждому каналу.

Сохраните секреты в отдельных обычных TXT-файлах вне каталога проекта, по одному значению в строке без кавычек и JSON. Не вставляйте ключи в команды оболочки или переписку. На Mac TextEdit должен сохранять обычный текст, не RTF. Ограничьте доступ владельцем: каталог 0700, файлы 0600. Client-Id — числовой идентификатор, отдельный от Api-Key.

Текущий первый подтверждённый кабинет: Ozon Deppa MSK. Уточнение рабочего процесса и команда запуска — [START_HERE](START_HERE.md).

## Установка

Распакуйте комплект в постоянную папку и откройте терминал в ней:

```bash
./install.sh
./mra-setup.command
./mra.command
```

install.sh выполняет проверки на синтетических данных, подключает комплектные знания и создаёт локальную БД; платные вызовы и запросы к площадкам не выполняются. Настройка спрашивает пути к файлам ключей, Client-Id, провайдера и имя оператора. Ключи в проект не копируются. При повторной настройке прежние настройки сохраняются в резервных JSON. Для данного пилота выберите OpenRouter/Luna; выбор модели сохраняется локально. В новой установке запускайте review-session с явным кабинетом по START_HERE.md. На исходном настроенном Mac обычный mra.command использует сохранённый кабинет.

Если после распаковки отсутствует право исполнения, выполните `chmod +x install.sh mra-cli mra.command mra-setup.command mra-test.command`. На macOS используйте штатное открытие разрешённого приложения через Finder при системном запросе; глобально отключать защиту не нужно.

## Проверка доступа и первый ответ

```bash
./mra-cli doctor
./mra-cli readiness
./mra-cli access-check --account acct_deppa_ozon --live
./mra-cli catalog-sync --account acct_deppa_ozon --live
./mra.command
```

access-check выполняет чтения отдельно для вопросов и отзывов. Отказ одного канала не означает отказ другого. catalog-sync обновляет ассортимент именно выбранного кабинета и сообщает о новинках и пробелах канона. Пропущенный товар не получает выдуманных характеристик: требуется проверка материала оператором.

Совместный тест выполняйте по [FIELD_TEST](FIELD_TEST.md). Модель вызывается только после отдельного подтверждения. HOLD сохраняет проверенный текст; публикация требует отдельного подтверждения точного текста и кабинета. accepted означает принятие API, published — подтверждённую API публикацию. Коллега проверяет видимость в кабинете и после модерации на площадке.

## Данные и резервная копия

Рабочее состояние находится в data/. Здесь обращения, запросы и ответы модели, источники ответа, действия оператора, состояния отправки, журналы API и ограничения. Секреты в журнал не записываются. Это частные рабочие данные, не файлы для GitHub. Сделайте резервную копию до переноса:

```bash
./mra-cli backup data/before-move.sqlite3
./mra-cli trace MESSAGE_ID --full
./mra-cli delivery-status
```

Команда backup использует SQLite Backup API и требует нового имени назначения. Для переноса или миграции: `./mra-cli migrate-db --source /absolute/source.sqlite3 --target /absolute/new.sqlite3`. Назначение не должно существовать. Сохраните исходник; затем проверьте новую копию командой `./mra-cli --db /absolute/new.sqlite3 doctor`. Для смены рабочей БД задаётся MRA_DB_PATH; выбранные пути покажет `./mra-cli project`. Скопируйте accounts.json/runtime.json отдельно и заново укажите местные пути к ключам. Журнал и limiter сохраняются вместе с БД.

Не запускайте две независимые копии БД для одного кабинета: между такими копиями нет общей блокировки отправок или квот. Все процессы одной установки должны использовать один файл SQLite. Автозапуск без человека пока не является принятым режимом.

## Если что-то не работает

- Пустые TXT: сначала сохраните значения в обычном тексте; проверьте, что Api-Key и Client-Id взяты из одного кабинета.
- HTTP 401/403: проверьте действительность ключа, права, IP-ограничения и подписку. Другая модель это не исправляет.
- 420/429: соблюдайте показанную паузу; она сохраняется после перезапуска. Не удаляйте БД лимитера. Механика: [RATE_LIMITS](RATE_LIMITS.md).
- Ошибка баланса модели: пополните API-баланс выбранного провайдера; автоматического переключения на другого платного провайдера нет.
- Нет товара или фактов: обновите каталог, проверьте соответствие артикула и наличие утверждённого канона. Изменять канон без решения владельца нельзя.
- Потерян результат отправки: используйте меню 9 или delivery-reconcile. Повторная отправка запрещена до установления результата. Восстановление подтверждённого отказа: [CONNECTORS](CONNECTORS.md).

Проверки без сети: `python3 -B tools/check.py` и `./mra-cli demo`. Они проверяют код; действительность ключей, доступ к API и реальную публикацию подтверждает отдельный натурный тест.

Основная навигация: [README](README.md). Операции: [OPERATIONS](OPERATIONS.md). Журналы: [AUDIT](AUDIT.md). Приёмка владельцем: [ACCEPTANCE](ACCEPTANCE.md).


## Управляемый старт

Основная точка запуска — `./start.command`. Стартер создаёт пустые TXT в private/credentials для всех шести кабинетов и для OpenRouter/OpenAI, спрашивает кабинет и провайдера, открывает нужные файлы на Mac, ожидает их сохранения, подготавливает базу и проверяет доступ к вопросам. Незаполненные файлы других кабинетов запуск выбранного кабинета не блокируют. Вызов модели начинается только после ввода СТАРТ. Настройку можно повторить через `./start.command --setup`.

По последнему решению владельца ключи могут храниться внутри проекта в **private/credentials**: Git и сборщик исходников исключают private/. На каталог выставляются права 0700, на TXT — 0600. Внешние пути к ключам остаются дополнительным способом ручной настройки. Содержимое ключей в настройки JSON не копируется. В ZIP исходников private/ не включается; файлы создаются стартером.

Стартер запускает сессию с человеком и не включает фоновую автопубликацию. План фонового режима: [AUTONOMOUS_MODE](AUTONOMOUS_MODE.md).
